# 小红书做图提示词库（xhs-prompt-library）

一个轻量知识库：把「市面上所有小红书信息图」拆成 **9 个可组合维度**，并给出可直接复制出图的提示词配方。

## 设计理念

小红书信息图不是一个单一东西，而是 **9 个维度叠加**出来的成品。一个图 = 形态 × 封面 × 布局 × 风格 × 主题色 × 尺寸 × 配色 × 字体 × 装饰。本库让使用者像选配方一样组合维度。

## 怎么查看

**双击 `index.html`** 即可，无需服务器、无需联网。

八页：
- ★ **示例画廊**（第一页）— 40 张真实出图作品，封面类型与内容形态各 10/10 全覆盖，覆盖 40 种版式 + 21 个主题色。点图展开完整提示词、配方码、复现要点、素材授权红线，可一键复制。
- ★ **自定义出图** — 选题预设 → 填主题 → 微调维度 → 复制提示词。
- **提示词合成器** — 选 9 个维度，实时拼出英文视觉指令 + 中文文案模板，一键复制。
  派生位会跟随上游自动匹配（选 form 自动配 cover/layout，选 style 自动配 palette），
  配方存 localStorage，关掉再开还在。撞上已知冲突会弹提示。
- **验证案例** — 5 个案例全文，含验证点与注意事项，可复制视觉指令。
- **全部词条** — 80 条，按维度切换，点卡片复制 prompt 片段。
- **抽卡** — 各维度各抽一条，凑出没见过的组合（可一次铺 8 组）。
- **风格配色搭配** — 12 组场景的风格×主题色参考，含具体推荐理由。
- **框架与体检** — 决策归属表、覆盖矩阵、冲突裁决。

改完 `data/*.json` 后跑 `node tools/build_web.js` 刷新页面数据。

## 先看哪个

**先看 `FRAMEWORK.md`** —— 它讲清 9 个维度分别由谁决定、按什么顺序拼。
其余文档都是它的展开。

## 每个 JSON 的字段约定

- `meta`：维度说明、来源、更新日期。
- `items[].code`：稳定编码（维度前缀 + 序号），配方里靠它引用，改中文名不影响引用。
- `items[].prompt`：可直接投入图像模型的**视觉指令**（英文，模型更稳）。
- `items[].zh / en / alias / desc / bestFor`：中文名、英文名、别名、描述、最佳适配。
- 中文文案（标题/要点）在**组合配方时**另行填入，不写进视觉指令。

## 怎么组合出一张图

1. 选定 `form`（讲什么）→ 通常决定 `cover` 和 `layout`。
2. 选 `style` + `palette` + `font` + `decor` 定调性。
3. 选 `size`（一般 3:4）。
4. 把各维度的 `prompt` 片段拼成一段英文视觉指令，再贴上中文文案模板（参考 `recipes.json`）。
5. 末尾固定加硬约束：`no watermark, no logo, no deformed fingers, natural features`。

## 冲突裁决（撞车时听谁的）

- 信息密度高 → 优先 `LO-15 dense` / `LO-03 card-grid`，而非 `LO-01 big-title`。
- 强观点 → 优先 `CV-01 大字报`，而非 `CV-04 拼贴`。
- 情绪内容 → 优先 `ST-03 warm` / `FT-02 手写`，而非 `ST-05 minimal`。

## 模型适配提示

- **GPT Image 2 / 商用模型**：稳定理解「风格+构图+约束」三段式。
- **免 key 通道（如 Sana）边界**：固定 seed 按 seed 出图、正文后段不参与、换 seed/画风前置不显形 → 只适合试构图，**不能证明画风效果**；画风验证走 keyed 通道。
- 提示词七段式最稳：主体 + 场景 + 风格 + 构图 + 光影 + 约束 + 尺寸。

## 体检

```bash
node tools/check_cases.js      # 结构体检（1340 项）
NODE_PATH=<jsdom> node tools/smoke-web.js   # 界面冒烟（80 项）
node tools/build_web.js        # 重新打包网页数据
```

查三件事：**案例引用完整性**（案例里每个维度码在词条表里真实存在）、
**网页引用完整性**（index.html 的 DATA_OF 映射、维度码、combo 键名）、**覆盖矩阵**。

不查：出图效果好不好、CTR 数字是否属实（那是实测与外部数据的事）。

当前基线：**体检 1340 全绿 + 界面冒烟 80 全绿 + 查重 0 雷同**；form×layout 组合空间 150，案例验证 5 条 + 画廊真实出图实测 40 组（26.7%）。

**必须跑冒烟**：静态检查测不出「单数/复数键名混用」这类整页白屏的运行时错误
（曾因此白屏两次，码层面全对）。详见 `怎么用.md` 与下方扩展约定。

## 复用与扩展

- 风格层直接复用并扩展了 **baoyu-xhs-images** 技能的 12 风格库；布局层溯源 **handraw-style/LAYOUTS.md** 的 117 布局。
- 扩展方式：在对应 `data/*.json` 的 `items` 里追加条目（code 顺延），`meta.count` 同步 +1；新配方加进 `recipes.json`，新案例加进 `cases.json`。
- 改完数据跑 `node tools/build_web.js` 刷新网页 bundle。
- `sizes.json` 的 `ratio` 字段是**断言用的机读字段**，不要从 `px` 字符串里解析（曾因此误判 5 项）。
- 网页 `file://` 直接双击打开，**不要在 index.html 里 fetch 本地 JSON**（CORS 会拦）——走 `assets/data-bundle.js`。
- **命名约定（必须遵守）**：`index.html` 内部维度键一律**单数**（`form`/`cover`/`style`…），
  bundle 数据表一律**复数**（`forms`/`covers`/`styles`…），靠 `DATA_OF` 互转。
  两边写成一样会整页白屏 —— 码层面全对，只有冒烟测得出来。`decor` 是例外，复数同形。
- **派生位语义**：改上游（form/style）永远重新跟随；手动改派生位（cover/layout/palette）只锁自己，不锁上游。
  `auto()` 必须在下游锁定信息更新**之后**调用。
- **复制即带尺寸**：所有复制入口统一经 `withSize()` 包装，输出自带 `1024×1536（3:4）`
  与出图参数说明 —— 不用回去找该用多大。冒烟有断言钉住「无入口漏包装」。
- **出图**：本库只出提示词，不代你调模型。纯静态网页调不动需要密钥的接口
  （API Key 无法安全落盘，且大概率被浏览器跨域拦掉）。做法是复制提示词 → 粘到任意文生图工具。
- **中文文字**：**实测零错字**，直接把中文文案写进提示词指定即可。
  （早期文档说「别指望模型渲染中文」是错的，已推翻——见 `怎么用.md`）
